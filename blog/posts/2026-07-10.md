Hello friends, I have a whole pile of stuff to talk about today. Mostly Agents
Runner stuff, but then the radio kept getting bigger and I kind of kept touching
things until there was a lot more done than I thought there would be.

So, first big one: Agents Runner has an MCP server now. Like, an actual stdio
MCP server with JSON-RPC tools for making tasks, starting them, listing them,
checking status, cancelling them, looking at logs, grabbing artifacts, managing
environments, making GitHub pull requests, and getting task metadata back out.

That is a lot. It means Runner is no longer only a thing you have to click
around in. Other tools can talk to it too, which is honestly pretty cool.

It also immediately found a very annoying real problem. The MCP initialization
could deadlock because the buffered reads were waiting too politely for more
data. So it uses `read1()` now and can handle partial frames instead of waiting
on `read()` for EOF or a full buffer. Tiny code change, but yea, the difference
between "it has an MCP server" and "the MCP server actually starts" is kind of
important.

The CLI got less weird too. `python -m agents_runner --help` shows help now
instead of opening the GUI, and special modes do not have to be the first
argument. It was one of those basic things where I was like, why was this ever
harder than that.

The old Get Agent Help path is gone. It had its own prompt template, preflight
stuff, UI button, plugin parameters, and weird special launch rules. Magic
Prompts is there instead now. You get starter prompts for finding a bug, adding
a feature, refactoring, looking around a codebase, or installing the contributor
template. Much easier to understand what is happening.

I also got agent configs into a much better place. They can be saved, loaded,
deleted, resolved, and connected to environments. OpenCode has separate TUI and
Web modes now too, instead of one setting that tried to mean both things. I like
being able to choose the thing I meant to choose.

The environment setup itself got bigger. It is five pages now: General Info,
Runtime & Agents, Desktop & Cache, GitHub Behavior, and AgentsNova Automation.
There are GPU overrides, OpenCode mode, maximum and cross-agent settings, cache
phases, branch names, pull request behavior, interactive prompts, automation,
validation locks, tooltips, compact navigation, and controls that only show up
when they matter.

That sounds like a lot because it is a lot. Environments were already carrying
most of those choices around anyway. Now they are actually visible instead of
being a surprise later.

There was a bunch of less visible Runner work too: workspaces, serialization,
cleanup, recovery, GitHub permissions, and launch-port guarding. The kind of
stuff that mostly gets your attention when it goes wrong. I am very happy to
make it go wrong less often.

Docker pulls got a process-level lock too, so a few tasks do not all try to pull
the same image at once. Pull output streams now, cancellation gets checked while
it is happening, and there is a timeout. Completed task files older than 30 days
get cleaned up as well. Old state sitting around forever is how the UI starts
acting haunted, and I do not enjoy that.

Okay, the `uv` thing. Runner containers set these defaults now when the
environment does not already have its own values:

```text
UV_PROJECT_ENVIRONMENT=/tmp/.uv-venv
UV_PYTHON_INSTALL_DIR=/tmp/.uv-python
```

That keeps `uv` from putting environment data in the mounted home directory.

It also touched Website Blog's TTS launcher because that launcher was assuming
`tts/.venv`. It uses this now:

```bash
TTS_VENV="${UV_PROJECT_ENVIRONMENT:-${TTS_DIR}/.venv}"
```

Then `uvicorn` comes from that environment. So it works in a Runner container
and it still works normally on the local setup. Good. Done. I like when two
repos stop disagreeing about where Python lives.

There is some visual Runner work in here too. Application themes can come from
album art now. They crossfade from fallback colors to song colors, and they do
not restart because somebody opened a menu. That fixed stale timers, snapping,
double blending, and transitions starting again at bad times. It is pretty when
you see it, but the part I liked was getting the state to stop fighting itself.

Runner also has Pyright in standard mode and basedpyright as the stricter
advisory check now. Pull request summaries collect type, formatting, lint, and
test results in one comment and keep updating it while workflows finish. I
really like that one. You do not have to go find five different checks and piece
it together yourself.

Then Website Blog got a lot of radio work.

The old `RadioBroadcaster` singleton is gone. It was a big stateful middle
thing, and it got replaced by a simpler HTTP passthrough. Reconnection moved to
the client with exponential backoff. Changing volume does not stop playback
anymore. Less code, better behavior. My favorite kind of cleanup.

`/radio` is a whole listening room now instead of a little widget that wanted to
be more important. It has full-screen cover art, colors from the art, an
animated SVG blob progress bar, server-side palette extraction with `sharp`,
listener heartbeats and counts, cross-tab state sync, responsive controls, focus
states, and a nav entry.

The container image has `ffmpeg` now because the probe endpoint needs it.
Switching channels fades out, changes streams, and fades back in. Playback state
follows between the floating player and the full radio page too. There is a lot
of stuff under that for something that looks like one page, but it is holding
together really nicely.

Mobile got a better version of it too. On a smaller screen it keeps the cover
art and track title, and leaves out a bunch of desktop metadata and Track Story
stuff. Previous and next channel buttons are back around play and pause in the
bottom bar, and the padding got tightened. Smaller is good. Hard to use is not.

The radio can do lyrics now as well. The probe reads the `lyrics-eng` FFprobe
tag into `lyricsEng`, and there are helper tests for empty values, whitespace,
casing, and instrumental markers.

On desktop there is an animated lyrics panel that recognizes things like
`[Verse]` and `[Chorus]`, uses the album colors for sections, handles the
animation in and out, fades the scroll edges, respects reduced-motion settings,
and gets the exact instrumental markers right. That is a lot of care for lyrics,
but lyrics change the whole feeling of a song. I am glad they did not just get
shoved in a box somewhere.

Lore got more support too. There are new Side Moments, password-gated content,
hints after failed password attempts, TTS lock overlays, fade-out unlocking,
artwork sets, Session 05 with five POV posts and forty artwork assets, fixed
`<thinking>` block handling, and lore-image viewport constraints.

The Website Blog is becoming a devlog and a story archive and a radio room and a
weird little museum with some locked doors. I mean that in the nicest possible
way.

`.agents/TOKENS.md` is the one place for blog and lore front matter, tokens, and
shortcodes now. That matters because otherwise you end up digging through old
posts trying to remember what a thing was supposed to do, and I have done enough
of that.

The content loader got safer too. Blog and lore loading use `path.relative` and
`path.isAbsolute` containment checks now instead of string-prefix comparisons.
There are tests for symlinks escaping the posts directory and sibling paths that
only look similar at the front. Good. That is the kind of security thing that
does not look exciting until it saves you from something dumb.

`agents-packages` has typed logger convenience methods now and already has its
`py.typed` marker, which helps with Runner's type work and the move toward
`midori_ai_logger` instead of standard-library `logging` imports.
`agents_template` is quieter right now, besides the earlier `.codex` to
`.agents` migration. That is fine. Not every repo has to be loud at the same
time.

So yea. Runner has more ways to be controlled, configured, and recovered.
Website Blog has a radio that feels way more like a place you can actually hang
out in, plus more lore support and better content handling underneath it.

That is a good amount of stuff. I am happy with it.

- Riley Midori
